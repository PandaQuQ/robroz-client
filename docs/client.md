# The desktop client

How the `client/` crate (`robroz-client`) behaves. It is a native iced 0.14 app, with one codebase for Windows, Linux and macOS, and no web view. Build and run it with [install.md](install.md#run-the-client). Environment variables are in [configuration.md, Client](configuration.md#client-robroz-client). How events and the look-and-feel layer fit together is in [architecture.md](https://github.com/PandaQuQ/robroz/blob/main/docs/architecture.md#客户端).

The desktop client UI is English by default. Switch to 中文 under Settings, General, Language / 语言 (see [Settings page](#settings-page)), or on the Can't reach the host page if the host has never answered. `ROBROZ_LANG=en|zh` overrides the saved choice for one run and is not written back. Quoted UI text below is what the English UI shows; the Chinese is in parentheses where it helps.

Card colours, status lines and actions come from `robroz-card`; layout and sizes come from `robroz-ui`'s `Skin`. The client does not invent its own palette. UI copy below is taken from `crates/robroz-ui/src/i18n/en.rs`.

## Layout

- Left: the conversation list, 220px wide (`crates/robroz-ui/src/view.rs:conversation_list`). There is no list heading and no row of page buttons. At the top, a round + button on the right opens the Add a bro (「引入一个 bro」) page: a name field, an avatar picker, and Add (「引入」). Creating a bro opens its DM. Below are groups and DMs, newest activity first, as 64px rows: a 48px avatar (a group shows up to three 24px avatars stacked with an 8px overlap, like the chat title capsule), the name in bold, the last-activity time on the right, and a one-line preview under the name. A row with no preview has no empty second line. A chat with unread messages has an 8px dot under its time, and the open chat's row sits on a `surface` fill with a border. An empty list shows No bros yet. Add your first one. (「还没有 bro，引入第一个」). That hint only appears once the host has listed the groups.
  - Search: a 48px capsule floats over the bottom of the list (placeholder Search, 「搜索」). It filters rows by name or preview, case-insensitively, and shows No matching messages (「没找到相关消息」) when nothing matches (`robroz_ui::home::row_matches`).
  - Self row: above the search capsule, a round avatar with your initial, your name from `GET /api/me`, and ›. It appears once `/api/me` has answered. It opens a menu with Settings (「设置」) and, after a divider, Sign out on this device (「在这台设备上退出」) in red. Every page that used to be a button under the list (Routines, Memories, Skills, Model, Web search, MCP, Allow rules) is now reached from Settings; see [Settings page](#settings-page). iced has no backdrop blur, so the floating buttons and the capsule use a translucent `surface` fill.
  - Right: the open conversation's message stream, or the matching page.
- Chat top bar (`view.rs:chat_header`): it sits over the top of the feed, which scrolls beneath it. On the left, the title capsule: up to three avatars and +N, the chat name, and a DM tag in a DM. On the right, a round ••• button. In a window narrower than 760px a round ‹ back button comes first, with the number of unread messages in the other chats beside it (capped at 99+, and absent at zero).
- The ••• menu (`view.rs:group_menu_popover`, 220px wide, 4px under the button) has View profile (「查看资料」) and Find in chat (「在聊天里找」). In a group, if you are an admin or created the group, it also has Rename (「改名」), Members (「成员」) and, after a divider, Delete group (「删除群」) in red. Those three show together or not at all. The rule is `robroz_ui::home::can_manage`: not a DM, and `me.role` is admin or `createdBy` is your user id. A group with no `createdBy` (made before the field existed) is admin-only, and with `/api/me` not loaded nothing is shown. A DM never shows them, even to an admin. In a DM with a bro you own, View profile opens that bro's avatar page instead.
- Group profile page: a round ‹ and a ••• on the top bar; a 96px avatar stack; the name; Edit (「编辑」) for people who can manage the group, which turns the name into a field with Save and Cancel (`PATCH /api/groups/{id}`); and a card (at most 720px, centred) with Routines, with {0} on (「{0} 个开着」) opening the Routines page, and, for people who can manage the group, Members with the member count (`GET /api/groups/{id}/members`). The profile ••• menu has Copy ID (「复制 ID」), then Delete group for people who can manage. Rename and Members in the chat menu open this page and start the edit or open the member list. The members page uses the same `settings_frame` as the Settings sub-pages: a column at most 720px wide and centred. Find in chat searches messages with `GET /api/groups/{id}/search`.
- Delete group asks first, in a 400px centred dialog: Delete {0}? (「删除 {0}？」) and Messages, tasks and routines are deleted, and running tasks are stopped. Bros are kept. (「聊天记录、任务和例行任务会删掉，正在跑的任务会停掉。bro 不会删。」), with Cancel on the left and a red Delete; then `DELETE /api/groups/{id}`. The host also refuses a caller who is not the creator or an admin (Only the creator or an admin can change this group) and a DM (DMs can't be renamed or deleted); the client does not offer those actions in either case.
- When the window is narrower than 760px (`robroz_ui::CHAT_COMPACT_WIDTH`), the sidebar is hidden: the list and the conversation each take the whole window. Open a chat to see it; the round ‹ in the chat top bar goes back. Pages that have their own round ‹ (the chat, Settings and its pages, profile, find in chat, members) do not get a second back bar; Add a bro gets a ‹ Chats (「‹ 聊天」) bar above it. (The phone-sized rules for touch targets and shortened bro names still start at 480px.)
- The stream is chat bubbles, not full-width rows. On macOS the UI font is Hiragino Sans GB (`/System/Library/Fonts/Hiragino Sans GB.ttc`, which fontdb can index; PingFang SC is not used, because it lives in a hidden asset path). On Windows it is Microsoft YaHei UI. Linux keeps the generic sans-serif. This is so a Chinese string is not drawn glyph by glyph from different fonts. Your own messages sit on the right in an ink bubble (inverted on the dark theme). A bro's items sit on the left behind a round avatar with its initial, with the bro's name above the first item of a group. Bubbles are at most 68% of the stream width and 560px (80% in a window narrower than 760px), with 16px corners, the corner nearest the sender 4px, and 10/14 padding. Cards are a fixed 360px wide (the stream width if that is smaller), left-aligned with the bubbles. Items from the same sender less than 2 minutes after the previous one form a group: 4px apart inside a group, 16px between groups. The time of the group's last item shows below it in 11px light text. The host only writes `messages` from a person, so every message is yours; status, approval, choice and confirm cards belong to a bro. A delivery with `bot_name` is drawn as that bro's card and joins or starts that bro's group under the usual 2-minute rule. A delivery without `bot_name` is drawn alone: left-aligned with the bro cards (indented by the avatar width plus its gap), with no avatar and no name, and it starts a new group.
- The group list comes from `GET /api/groups`. If `ROBROZ_GROUPS` is set (comma-separated `id` or `id=name` items), only those groups are shown.
- Opening a conversation marks it read (`POST /api/groups/{id}/read`). Unread counts come from `GET /api/unread`.
- If the host has never answered, the sidebar stays empty and the main pane centres Can't reach the host (「连不上宿主」), with the host address on a lighter line below it and, 12px to the right, a short light-grey reason when there is one: Connection refused (「连接被拒绝」), Timed out (「超时」), or Host not found (「找不到主机」); otherwise no reason is shown, and the raw `io:` / `os error` text is never shown. Below that address/reason line, with a 24px gap, are a Language / 语言 row and an Appearance / 「外观」 row, each a label with segmented buttons (English / 中文 and System / Light / Dark), centred and at most 360px wide, with the connection form under them (`client/src/main.rs:language_row`). This pane is the only place those segmented rows remain; in the Settings page they are lists with a tick. Choosing a language or appearance switches immediately and is saved to `lang` or `theme` under the client config folder; `ROBROZ_LANG` still only overrides the current run. While the host has never answered, the footer is hidden, because the pane already shows why. The client retries on the poll interval. After the host has answered once, a later failure keeps what is already on screen and shows the error in the bottom bar.
- `--fake` / `ROBROZ_FAKE=1` plays a scripted run offline. `--gallery` lays out every card state for design review. Fake and gallery runs do not read or write the saved `lang` or `theme` files. In those runs, `ROBROZ_THEME=light|dark` sets the appearance; if it is unset, the run is Light.
- Every line from the composer goes to `POST /api/groups/{id}/say`. In a DM the whole message goes to that bro, or attaches as a follow-up if the bro already has an open task. In a group, every bro gets a turn; a leading `@name` or `＠name` gives that bro the first turn. The composer hint in a group is Message the group, or @name a bro.

## Settings page

Open it from the self row's menu (Settings, 「设置」). On a wide window it fills the main pane next to the list; below 760px it takes the whole window, with a round ‹ back button in the title row. Code: rows and groups in `crates/robroz-ui/src/settings.rs` (`landing`), layout in `crates/robroz-ui/src/view.rs` (`settings_page`, `settings_choice_page`, `settings_sub_page`, `settings_frame`), navigation in `client/src/main.rs` (`settings_view`, `Action::SettingsGo`). Sizes come from `robroz_tokens::settings`.

The title is Settings (「设置」), 20px. Under it are three groups of rows, each a card (16px radius, `surface` fill, 1px border) with a 12px `text3` group title 8px above it, and 24px between groups. A row is 44px high with 16px side padding and a 1px divider between rows. Each row paints `surface` (hover `control_hover`), so it does not leave a hole in the card. Its label is on the left, then the current value in `text2` where there is one, then ›.

| Group | Rows, in order |
| --- | --- |
| General (「通用」) | Language / 语言 (value: the language's own name, English or 中文); Appearance (「外观」; value: System, Light or Dark) |
| Bros (zh 「bro」) | Model, Web search, MCP, Skills, Memories, Routines, Allow rules (「模型」「联网搜索」「MCP」「技能」「记忆」「例行任务」「放行规则」) |
| Connection (「连接」) | Host (「地址」; value: the host address without `http://` or `https://` and without a trailing `/`, empty if there is none) |

Below the groups:

- **Sign out on this device** (「在这台设备上退出」) is a card of its own, one 44px row with red centred text. It deletes the token stored on this device only (the OS keychain entry or the `token` file; a token from `ROBROZ_TOKEN` cannot be deleted, but the session still ends), clears what the client holds, and shows the connection form. It does not change anything on the host. The same entry is in the self row's menu.
- The **version line** is centred, 12px `text3`: `robroz-client <version> (<git sha>)`, with ` dirty` inside the parentheses for a dirty checkout and `unknown` for a build without git (`client/src/cli.rs:version_string`). There is 24px below it, plus the safe-area inset on a phone.

What each row opens:

- **Language and Appearance** open a choice page: one card with the options, and a tick (accent colour) on the current one. Picking an option applies it at once and saves it; you leave with the round ‹. The options are English and 中文, or System, Light and Dark.
- **Host** opens the same connection form as the Can't reach the host page (Host and Token, Connect; hints such as Set by ROBROZ_HOST and Unencrypted. Use HTTPS for remote hosts.). The page title is Connection.
- **The seven Bros rows** open the Model, Web search, MCP, Skills, Memories, Routines and Allow rules pages. Their ‹ goes back to Settings. The same pages opened from elsewhere (Set up on a delivery card, Routines in a group profile) go back to the chat instead.

Every sub-page, on a wide desktop window too, uses the same frame (`settings_frame`): a round ‹ and a 20px bold title on one row (40px button plus 16px of padding), then a column at most 720px wide and centred, 16px from the sides, with 24px under the last item. A page may add controls at the right end of the title row; MCP puts its connected count and Add there. Pages no longer draw their own outer card or title.

## Language

The Language / 语言 row (`SettingsLanguage`; the same text in both UIs) is the first row of Settings, General. It also appears, as a segmented row, on the Can't reach the host page when the host has never answered. The options are English and 中文 (each name stays in its own language in both UIs). The choice is saved as one line (`en` or `zh`) in the `lang` file under the client config folder (`ROBROZ_CONFIG_DIR` if set, otherwise the usual per-OS folder; see [configuration.md](configuration.md)). `ROBROZ_LANG=en|zh` wins for the current run (`zh-CN`, `en_GB.UTF-8` and similar also work), is never written back, and unknown values are ignored. No file, or an unreadable one, means English. There is no footer switch.

Changing the language redraws on-screen cards and conversation-list previews immediately, including You (「我」) on cards. Status cards are drawn from the event each time; previews are cached and rebuilt from the stored events on the switch (`client/src/model.rs`, `Previews::redraw`).

## Appearance

The Appearance / 「外观」 row (`SettingsAppearance`) is the second row of Settings, General, and also appears under the Language row on the Can't reach the host page. It opens a choice page with System / 「跟随系统」 (`SettingsThemeSystem`), Light / 「浅色」 (`ClientThemeLight`), and Dark / 「深色」 (`ClientThemeDark`). The default is System. Choosing System follows the operating system live (`iced::system::theme_changes()` in `client/src/main.rs`); Light and Dark pin the scheme, including the window frame. The choice is saved as one line (`system`, `light`, or `dark`) in a `theme` file next to `lang`. No file, or an unreadable one, means System. The footer no longer has a Dark control.

`ROBROZ_THEME=light|dark` is honoured only in fake and gallery runs, is never written back, and causes those runs to ignore the saved file. A fake or gallery run with the variable unset is Light, so screenshots do not follow the desktop. In a normal run the variable is ignored.

## Cards in the message stream

| Card | How it is shown |
| --- | --- |
| Text message | The body in your own bubble, on the right. |
| Image / file message | A labelled chip (Image / File) and the name on one line inside your bubble; there is no viewer. |
| Status card | One per task, updated in place by `taskId`. Bro name on the left, status line on the right. Rules below. |
| Delivery card | A summary plus a monospace path relative to the group folder, display only, not clickable. When `briefing` is true, a Briefing (「简报」) badge is added in the corner (`robroz_card::briefing_badge`). When `needsSetup` is `"search"` or `"model"`, a Set up (「去设置」) button is added on the right, and a grey line under the path says Skipped web search: not set up yet or Skipped: no model set up yet. When `failure` is set, the whole card becomes the grey Couldn't finish: {reason} line, with no path and no grey hint; if `needsSetup` is also set, Set up still appears on the right. A dead run's `failure` 「没写出结果」 is shown as Finished with no result, without the Couldn't finish: prefix (`robroz_card::failure_line`). |
| Choice card | Updated in place by `id`. Can be answered (`POST /api/choices/{id}/answer`) once. Who answered is described below. |
| Approval card | Approve and Deny, once. After an answer the footnote is two spans, with no "·" between them: Approved by You and the time when this client answered; Approved by {name} and the time when someone else did; Denied by You or Denied by {name} and the time for a denial. When `answeredBy` is `null`, the text is just Approved or Denied, plus the time. |
| Confirm card | See Confirm cards below. |

An event whose `type` the client does not recognise is skipped; other cards are unaffected.

### Status cards

A status card is a plain bro card (the bro bubble colour with a 1px border). The bro name is only in the group header, not inside the card. A small status dot sits 8px left of the status word: accent (`#c8572a` light, `#e0743f` dark) for a running card, green for done, amber for stuck, grey for queued, a dead run, waiting on approval and a failure. There is no filled bar. Wherever this section says "grey", "amber" or "green" for a state, that is the dot's colour. The status word (and "Step n of m", when shown) is left-aligned after the dot; a flexible gap pushes the Take over in DM button to the right. That button is outlined (transparent fill, 1px line border, ink text) with 6px vertical and 12px horizontal padding.

- `queued`: grey Queued (「排队」).
- `running` with `containerUp`: Running (「进行」). If `progress` is the Router step form (`{n}/{m} 步`, shown as Step n of m), it sits immediately to the left of the status word in a lighter colour, with a 12px gap and no separator; on a narrow window it is dropped rather than wrapping or shortening the status word. Any other `progress` is a light-grey line under the status row, shortened with "…" when it is too long. If there is no progress, that row is not reserved.
- `running` with `containerUp` false: grey Finished with no result, no action. This only appears in old data; the host now ends a dead run as `done` plus `failure` 「没写出结果」, and that card is also shown as grey Finished with no result, without Couldn't finish:.
- `blocked` with `waitingFor` `approval`: not treated as a takeover. Grey Needs your approval (「等你批准」), no button; answer the approval card beside it.
- `blocked` with `waitingFor` `takeover`, or with the field missing (an older host): amber Stuck (「卡住」) plus Take over in DM (「去私聊接管」). That button currently only logs; it is not wired up yet.
- `done`: Done (「完成」). With a `failure`, a grey Couldn't finish: {reason} (or Finished with no result when `failure` is 「没写出结果」), never the green Done, and no button.

Host-written `label`, `failure` and `progress` values on the wire are still Chinese. The client maps known strings into the English above.

### Conversation list previews

- When a live run has a progress line, the preview uses that line (mapped into the UI language), for example Ada: Thinking about a reply or Ada: Step 2 of 3, not Ada: Running. Long text is cut to the column width with "…".
- When `waitingFor` is `approval`, the bro's owner sees Ada: Needs your approval (「Ada：等你批准」); anyone else, and anyone while `/api/me` or the bro's owner is not known, sees Ada: Waiting for this bro's owner (「Ada：等这个 bro 的主人审批」, `Key::ApprovalWaitingFor`), the same sentence as the card (`client/src/model.rs:preview_of`). The preview is not replaced by an approval card's summary that arrives at the same time.
- An approval reminder (`approval_reminder`) uses the same sentences as the in-chat row: the owner sees {0} is waiting for your approval in {1} (「{0} 在 {1} 等你审批」, `Key::ApprovalDmReminder`); anyone else sees Waiting for this bro's owner (「等这个 bro 的主人审批」, `Key::ApprovalWaitingFor`).
- With no progress, or when the task is done, stuck, or failed, the preview uses the status line as usual.
- Switching the language redraws every preview immediately from the events the client already has.

### Who answered

When this client answers an approval, choice or confirm card, it sends `ROBROZ_USER_NAME` as `answeredBy` (the computer's hostname if that is unset, or `robroz` if the hostname cannot be read; first non-empty line only, at most 40 characters).

- If the returned `answeredBy` matches the name this client sent, the footnote uses You (「我」). If it is a different name, that name is shown. If it is `null`, no name is shown, only Approved (or the matching word) and the time.
- The time always comes from the host's `answeredAt`.
- Two devices must not share the same name, or each will show the other's answers as You.
- If someone else answered first (409), the card updates in place with that result.

## Confirm cards

- **Memory card:** a Memory tag in the top left, then the full text and a one-line scope (All bros or Only Ada), with Remember and Not now. After an answer the footnote is Remembered · You · HH:MM, or a grey Dismissed · … (the client joins those parts with "·"). Forgetting a pending memory on the Memories page updates the card to Dismissed · HH:MM, with no name.
- **Skill card:** a Skill tag in the top left, the title and `slug`, and a scope line under the instructions. Instructions show the first three lines by default; Show all opens them, Show less folds them back. The buttons are Save and Not now; after an answer the footnote is Saved · You · HH:MM or a grey Dismissed · …. After Save, the skill still has to be enabled in a group before it is added to the prompt.
- **Folding:** if one task has more than three pending confirm cards, from the fourth onwards they collapse to {N} more to review. Open that row to confirm them one by one.

## Memories page

Open it from Settings, Bros, Memories (「记忆」).

- Entries are grouped by scope: All bros first, then one group per bro (Only Ada). Inside a group, To review and Remembered N are listed separately; a group that only has kept items still shows Remembered N. Each item shows the text, a kind (Profile, Habit, Project) and the updated time. An empty page shows Nothing remembered yet.
- Pending items only have Remember and Not now, which call the confirm-card API with `confirmId`. The card in the chat updates with them.
- Kept items can be Edit (`PATCH`) or Forget (`DELETE`). Forget asks Forget this? Bros won't use it again. and then removes the item from the list.
- Add memory first asks for a scope. Until one is chosen, that row says Choose who can use this; after a choice it becomes the grey Only Bob can use this or All bros can use this. The row always takes space, so Save does not jump.
- Save is grey when the text is empty, unchanged, over 2000 characters, or no scope is chosen. After a success the updated time refreshes and Saved appears beside it. A failure shows Not saved: {reason} in place, and the draft is kept.

## Skills page

Open it from Settings, Bros, Skills (「技能」). The layout matches the Memories page.

- Entries are grouped by scope. Inside a group, To review and Saved N are listed separately. Each item shows the title, `slug` and the first three lines of the instructions. An empty page shows No skills saved yet.
- Pending items have Save and Not now, which call the confirm-card API with `confirmId`.
- Saved items can be Edit (`PATCH`; `slug` cannot change) or Delete (`DELETE`). Delete asks Delete this? Bros won't use it again.
- A saved item has Use in these groups, with one switch per group: on is `PUT /api/groups/{id}/skills/{slug}`, off is `DELETE`. Opening the page first reads `GET /api/groups/{id}/skills`. Until that returns, the switch is grey and disabled, with Loading beside it; a failed read shows Couldn't load.
- Add skill needs a short English name (`slug`: lowercase letters, digits and hyphens), a title (at most 80 characters), instructions (at most 8,000 characters), and a scope. The scope hint, the greyed-out Save, Saved and Not saved: {reason} behave as on the Memories page.

## Model page

Open Settings, Bros, Model (「模型」), or Set up on a delivery card with `needsSetup: "model"`. The API is `GET` / `PUT /api/settings/model` and `POST /api/settings/model/test` ([api.md](https://github.com/PandaQuQ/robroz/blob/main/docs/api.md#model-settings)). Code: state and copy in `crates/robroz-ui/src/cards/model.rs`, layout in `crates/robroz-ui/src/view.rs:model_panel`, requests in `client/src/api.rs`, message handling in `client/src/main.rs:on_model_action`. The page shows only the model: Language, Appearance and Connection are on the Settings page, and the page uses the standard sub-page frame (round ‹, 20px title, at most 720px wide).

- **On open** the page `GET`s once and fills the form with the effective settings. When all three fields are empty it shows No model set up yet. A failed read shows the reason on the page (Can't reach the host when the host is down).
- **Provider:** a client-side shortcut; the host has no provider list. The options are, in order, Gemini (recommended), Groq, OpenRouter, Ollama, Custom. The empty-value placeholder is Choose a provider. Picking one fills the matching OpenAI-compatible URL (no trailing `/`); the model name and key still have to be entered. If the URL is edited so it no longer matches that shortcut, the provider becomes Custom. Picking Custom does not change a URL that is already filled in. When OpenRouter is selected, a grey line under the model name says Free model names end in :free.
- **URL / Model name / Key:** the labels are URL, Model name and Key (optional). Placeholders do not repeat the labels. The URL box starts empty; the model-name box uses that provider's example (Gemini `gemini-3.8-flash`, Groq `llama-3.3-70b-versatile`, OpenRouter `meta-llama/llama-3.3-70b-instruct:free`, Ollama `llama3.2`, Custom left empty). The key box also starts empty. Every provider, including Ollama, shows the key field.
- **Key** uses the shared `MaskedKey`. A stored key shows Set · last4, with only Clear beside it (the client joins Set and the last four characters with "·"). Clear does not send a request yet: the field changes to the grey Deleted on save plus Undo; Save is what sets `key` to `null` (that field then falls back to the environment). Save only submits the URL, model name and key changes in this form; it does not clear the other two fields.
- **Save:** both URL and model name are required, and the URL must start with `http://` or `https://`. The key is optional; the client no longer checks for a missing key locally. After a successful `PUT` the client automatically `POST`s `…/test` once. The result is Testing…, then ink Working with a green dot, or Saved, but can't connect: {reason}. When the cloud service is missing a key or the key is wrong, `/test` returns `error` 「密钥不对或没填」, and the page shows Saved, but can't connect: key is wrong or missing, not a raw 401. A failed save shows Not saved: {reason}.
- **From environment variables:** only shown when the host returns `source: "env"`. If the field is absent, nothing is labelled and nothing is guessed.
- **Set up:** shown only when a delivery card's `needsSetup` is `"model"`. The button appears whenever that field is present, even without a `failure`. Tapping it opens this page.

## Web search page

Open Settings, Bros, Web search (「联网搜索」), or Set up on a delivery card. The API is `GET` / `PUT /api/settings/search` and `POST /api/settings/search/test` ([api.md](https://github.com/PandaQuQ/robroz/blob/main/docs/api.md#search-settings)). Code: state and copy in `crates/robroz-ui/src/cards/search.rs`, layout in `crates/robroz-ui/src/view.rs:search_panel`, requests in `client/src/api.rs`, message handling in `client/src/main.rs:on_search_action`.

- **On open** the page `GET`s once and fills the form with the effective settings. When nothing is in effect (`provider` is null) and no service is selected, it shows Web search isn't set up yet. A failed read shows the reason on the page (Can't reach the host when the host is down).
- **From environment variables:** a tag next to the title, only when the optional `source` field in the response is `"env"`. `"settings"`, a missing value or an unknown value are not shown and not guessed. After a save the host returns `source: "settings"` and the tag disappears.
- **Provider:** Brave or SearXNG, two buttons, the selected one highlighted.
- **Brave key:** a masked field; the client never reads the raw key back.
  - When the host already has a key (`hasKey` is true), the input is hidden and the row shows Set · last4 (the `keyLast4` value, for example Set · abcd; or just Set when there is no last four). Only Clear sits beside it.
  - Clear first marks the key for deletion, shows the grey Deleted on save, and offers Undo. Save is what actually clears it; Undo returns to Set · …. The save sends `PUT {"provider":null,"url":null,"key":null}`, which clears the service, URL and key in the settings API, then falls back field by field to the environment. With no environment values the page returns to Web search isn't set up yet. Values that come from the environment cannot be cleared: after that save the page still shows the environment settings and From environment variables.
  - With no stored key the input is shown, with the placeholder API key.
- **SearXNG URL:** one input, placeholder SearXNG URL, e.g. http://127.0.0.1:8888. There is no Clear button under SearXNG.
- **Save:** grey when no service is selected or a request is in flight. Pressing Enter in an input also saves. The `PUT` only includes the fields that are needed: Brave with a new key sends `key`; Brave with a stored key sends only `{"provider":"brave"}`; SearXNG sends `provider` and `url` and leaves the key alone.
  - Local checks that fail are not sent: Brave with no stored key and nothing typed shows Enter a key; SearXNG with no URL shows Enter a URL.
  - A failed save shows Not saved: {reason} in place. The reason is the host's error text (see the 400 list in api.md), or Not saved: Can't reach the host when the host is down.
  - After a successful save the page **tests the connection once** (`POST …/test`). Next to Save it shows Testing…, then Working, or Saved, but can't connect: {reason}. A leading 「连不上：」 in the host's error is stripped so it is not doubled. There is no separate test button on the page.
- **Set up:** shown only when a delivery card's `needsSetup` is `"search"`, not by matching Web search isn't set up yet. The button appears whenever that field is present, even without a `failure`. When `web_search` is not configured the host returns that sentence to the model, the task usually still writes a result, and the delivery has no `failure`: the card still shows Set up, with the grey line Skipped web search: not set up yet under the path. With a `failure` the card is the grey Couldn't finish: {reason}, with no path and no grey hint, and the button stays on the right. Tapping Set up opens this page. You can also open Web search from Settings, Bros.

## MCP page

Open it from Settings, Bros, MCP. This page manages MCP servers on the host: add, edit, delete, connect, disconnect, test a connection, list tools, enable per group, and approve a stdio start command. On a phone the page is read-only; see [Phone app](#phone-app). The API is in [search-and-mcp.md](https://github.com/PandaQuQ/robroz/blob/main/docs/search-and-mcp.md#mcp) and [api.md](https://github.com/PandaQuQ/robroz/blob/main/docs/api.md). Code: state and copy in `crates/robroz-ui/src/cards/mcp.rs`, masked keys in `crates/robroz-ui/src/cards/secret.rs` (shared with the Web search page), layout in `crates/robroz-ui/src/view.rs:mcp_panel` and `mcp_row`, requests in `client/src/api.rs`, message handling in `client/src/main.rs:on_mcp_action`.

- **On open** the page reads `GET /api/mcp/servers`, then `GET /api/groups/{id}/mcp` for each conversation in the left list. A failed read shows the reason on the page (Can't reach the host when the host is down).
- **Title row:** the standard sub-page frame (round ‹, MCP as the 20px title). At its right end are the connected count and Add server (「加一台」). The count, {0} connected (「已连接 {0} 个」), is 13px muted (`text2`) text, not a capsule or a button, and is hidden while nothing is connected. Add server is hidden while a form is open, and when `Skin::phone` is set (the iced preview skin with `ROBROZ_PHONE=1`, and the shipped Slint phone app). A narrow desktop window keeps it.
- **Empty state:** with no servers and no open form, No MCP servers yet and Click “Add server” to connect tools your bros can use.
- **Transport capsules:** All, stdio and HTTP (「全部」「stdio」「HTTP」), 36px high, shown only when the host has servers of both transports. The selected one is inverted; pressing it again returns to All. If a capsule stops being shown (for example the last HTTP server is deleted), the list falls back to All. They filter by transport because `contract-v0.3.0` has no category field; real categories wait for a later contract.
- **List:** newest `updatedAt` first. Each row is 64px: a 44px rounded tile with the first letter or digit of the name in upper case (`·` if there is none; the contract has no icon field either), the name in semibold, and a grey line under it. The grey line is the latest test result when there is one (Testing…, Working · N tools, or Can't connect: {reason}); otherwise N tools (1 tool when the count is one), Not counted yet when it has not been counted, or Approve the command to load its tools (「批准命令后才能加载工具」) for a stdio server whose command is not approved (`transport` is stdio and `commandApproved` is not true). That line has a 6px `status.blocked` yellow dot in front of it until a test result replaces it (`mcp::shows_approval_status`). The line wraps to at most two lines, then an ellipsis (`mcp::clamp_subtitle` / `subtitle_cols`). Rows carry no extra tag. On the right is Connect (「连接」) or Connected. When `Skin::phone` is set, Connect is hidden and only the Connected label remains; a narrow desktop window keeps Connect. Click the tile or name to expand or collapse the row.
- **Connected** (`mcp::is_connected`) means the server is enabled and, for stdio, its command is approved. It is shown as muted `text2` text, Connected (「已连接」), after a 6px `status.done` green dot, and is not a button. A server that is enabled but whose stdio command is not approved is not connected: it shows Connect, and its expanded row still has Disconnect (both are hidden when `Skin::phone` is set).
- **Connect** does the first step that is missing:
  - Server disabled: `PATCH /api/mcp/servers/{id}` `{"enabled":true}`, then `POST /api/mcp/servers/{id}/test`. A failed `PATCH` shows Not saved: {reason} under the row.
  - Server enabled, stdio command not approved: only `POST …/test`. The host answers 409 `command_not_approved`, the row expands, and the approval panel opens (below).
  - After a successful test the row shows Working · N tools; the tool list is fetched when the row is expanded.
- **Once expanded,** in order, with 16px between blocks: the tool list (or the command-approval panel, below); Use in these groups; and the action row. When `Skin::phone` is set, the command-approval panel, Use in these groups and the action row are hidden, so an expanded row can still show the tool list.
  - The tool list comes from `GET /api/mcp/servers/{id}/tools`, fetched the first time the row is expanded and cached after that. While loading it shows Loading, a failure is Can't connect: {reason}, and no tools is This server has no tools yet. Each item is the tool name, with Needs your approval beside it when `needsApproval` is true, and a grey description line when `description` is set.
  - Use in these groups: one 44px row per conversation in the left list (`robroz_tokens::mcp::GROUP_ROW`, the same on wide and narrow windows), the name on the left and a switch right-aligned. On is `PUT /api/groups/{id}/mcp/{serverId}`, off is `DELETE`. Until the real state is loaded the switch is grey and disabled, with Loading under the name; a failed read shows Couldn't load.
  - Actions, in order: Edit (「改」), Disconnect (「断开」), Delete (「删除」). Disconnect is there whenever the server is enabled (`mcp::shows_disconnect`), including an enabled stdio server whose command is not approved; it is `PATCH /api/mcp/servers/{id}` `{"enabled":false}` and does not test. Delete is an outline button in `danger` text, always last. It first asks Delete this server? Groups won't use it any more.; a second, filled Delete sends `DELETE` (a 404 is treated as already deleted), and Cancel folds the prompt back.
  - A failure under the row shows Not saved: {reason}.
- **Add server / Edit:** the form appears at the top of the list (add) or replaces that row in place (edit). Each input has a small label above it so the field stays identifiable once it has a value:
  - Name: required, at most 80 characters. The placeholder is the same as the label (Name).
  - stdio and HTTP choose the transport; stdio is the default.
  - stdio: Command (required) and Arguments (space-separated) (split on whitespace, so one argument cannot contain a space). The placeholders are the same as the labels.
  - HTTP: URL (must start with `http://` or `https://`). The placeholder is URL.
  - Add a secret adds a row: Secret name (no whitespace), Environment variables or Request headers (stdio defaults to Environment variables, HTTP to Request headers), Remove, and Secret. The placeholders are Secret name and Secret.
  - When a local check fails, Save is grey and one of these hints is shown: Enter a name, Name: max 80 characters, Enter a start command, Enter a URL, The URL must start with http:// or https://, Enter a secret name, Secret names can't contain spaces, Enter a value for the new secret. When the host rejects the save, Not saved: {reason} is shown in place.
  - Edit fills in the name, command, arguments and URL, and **does not fill in the raw secret**.
- **Secrets:** the input uses the same `MaskedKey` as the Web search and Model pages. A stored secret (`hasKey` is true) hides the input and shows Set · last4 (or just Set), with only Clear beside it.
  - Clear does not send a request immediately: the field changes to the grey Deleted on save plus Undo. Save is what sends this secret as `key: null`, and the host then deletes the whole entry (including the name). Undo returns to Set · ….
  - A stored secret that was not changed is omitted from the `PATCH`, and the host keeps the previous value.
  - Remove only takes the row out of the form. Secrets the `PATCH` does not mention are kept, so Remove plus Save **does not delete** a stored secret; use Clear and then Save.
- **After Save:** create uses `POST /api/mcp/servers`, edit uses `PATCH`. On success the row expands itself, **tests the connection once** (`POST …/test`) and reloads the tools. Under the name it shows Testing…, then Working · N tools (or just Working when there is no count), or Can't connect: {reason}. There is no separate test button on the page; Connect is the way to run the test again.
- **Command approval:** a stdio server's command and arguments must be approved before the host will start it ([search-and-mcp.md](https://github.com/PandaQuQ/robroz/blob/main/docs/search-and-mcp.md#mcp)). When `…/test` or `…/tools` returns 409 `command_not_approved`, the row expands and the tool list is replaced by the approval panel:
  - A Command label over the command, an Arguments label over each argument on its own line, all monospace, wrapping rather than truncated. The command and arguments come from the 409 body, and are what the host would start.
  - A grey line: This command runs on your computer.
  - Approve and run sends `POST /api/mcp/servers/{id}/approve-command`. On success the panel folds away and the page runs `POST …/test` and `GET …/tools` again automatically. A failure shows Approval failed: {reason} (「批准失败：{0}」) in accent colour under the buttons.
  - Cancel only folds the panel, with no request; the row returns to Approve the command to load its tools. Expanding it again reloads the tools, and another 409 brings the panel back.
  - A new or edited stdio server is tested right after save, so the approval panel appears immediately.

## Allow rules page

Open it from Settings, Bros, Allow rules (「放行规则」). It lists allow rules that have already been confirmed. Adding or deleting a rule from this page returns 202 and an `approvalId`; the client then `GET /api/approvals/{id}` and shows the confirm card on this page (a new rule under the input, a deletion in place of that row). `POST /api/approvals/{id}/approve` / `deny` answers it, and only an admin may: `botId` is `SETTINGS_APPROVAL_BOT_ID` (`"settings"`), which belongs to no bro, and the host's `may_answer` lets only an admin answer such a card (anyone may propose one). The client reads the role from `GET /api/me` (`crates/robroz-ui/src/cards/review_rules.rs:may_decide`). Add and Delete are shown only to an admin (`review_rules::shows_edit_controls` / `can_decide`); a member sees neither. There is no `taskId`, the card is not sent to any chat, stream or unread count, and it works even with no bros. The client also filters these cards out of the conversation stream. After an approval the list is fetched again; a denial just dismisses the card. The page has no outer card or heading of its own; it uses the standard sub-page frame (round ‹, 20px title, at most 720px wide). The API is in [api.md, Allow rules](https://github.com/PandaQuQ/robroz/blob/main/docs/api.md#allow-rules); the design is in [design/auto-review.md](https://github.com/PandaQuQ/robroz/blob/main/docs/design/auto-review.md). Code: state and copy in `crates/robroz-ui/src/cards/review_rules.rs`, layout in `crates/robroz-ui/src/view.rs:review_rules_panel`, requests in `client/src/api.rs`, message handling in `client/src/main.rs:on_review_action`.

- **Add a rule:** only an admin sees this. A one-line input at the top with Add (「添加」) beside it. The placeholder, One sentence, e.g. Allow merging PRs when CI is green, is a wrapping `text3` hint under the empty field (the field's own placeholder is left blank, because an iced `TextInput` placeholder cannot wrap). Submitting it returns 202 and an `approvalId`; the confirm card is shown under the input. If the text is too long, the page shows Max {0} characters. Remove {1} more.
- **One-line rule:** the rule text, a grey Added {date} line under it (from `createdAt`), and, for an admin, Delete on the right. Delete is an outline button in `danger` text, the same as MCP Delete (`danger_outline_button`). There is no switch and no edit. After Delete the rule stays in the list until it is confirmed; the confirm card is shown in that row.
- **Confirm card** (on this settings page, reusing the confirm layout): no bold title. The body is the rule text. What else shows depends on who is looking (`view.rs:rule_confirm_on_page`):
  - An admin sees a grey line under the body, Confirm to add this allow rule or Confirm to delete this rule, and the buttons: Add / Not now for an add, a red Delete rule / Not now for a delete.
  - Anyone else sees Waiting for an admin (「等管理员确认」) above the rule text, and no buttons at all, not greyed out, and not the Confirm to … line, because they cannot confirm. The same holds while `/api/me` has not answered: no role, no buttons.
  - If the card was already handled elsewhere, it is dismissed and a grey This card was already handled appears on the page, then the list is fetched again.
- **Expired card:** when `decision` is `denied` and `reason` equals the contract constant `APPROVAL_EXPIRED_REASON` (「审批已过期」), the card shows Expired, and the footnote Expired with no approval plus the time as two spans. The buttons are locked. It does not say Denied by You, and there is no "try again". In a chat an expired card still has a grey Expired dot in the top right, and keeps the action row.
- **Approval cards in a group (v0.2 host, the card has `ownerUserId`):** a card a bro raises (a task approval, an MCP tool call, or a card from `POST /api/groups/{id}/approvals` that auto-review did not allow) stays in the group it was raised in. Only the bro's owner may answer it; an admin who does not own the bro is refused too (the host's `may_answer`, see [permissions.md](https://github.com/PandaQuQ/robroz/blob/main/docs/permissions.md#who-may-answer-and-where-the-card-goes-v02)). The client follows that rule (`crates/robroz-ui/src/cards/group_approval.rs`, `view.rs:group_approval_card`). When a card is blocked, an extra grey line reads Blocked because: plus the reason.
  - **Owner, in a group:** a status dot and word, what the bro wants, then Approve (「批准」) and Deny (「拒绝」) right-aligned. After an answer one line shows Approved by you at {time} or Denied by you at {time} (「你于 {0} 批准」 / 「你于 {0} 拒绝」). In a DM the owner keeps the card described under Cards in the message stream.
  - **Anyone else, and anyone while `/api/me` has not answered:** the status reads Waiting for this bro's owner (「等这个 bro 的主人审批」) and there are no buttons, not greyed out. After an answer: Approved by {owner} at {time} or Denied by {owner} at {time}. If a 403 `not_owner` still comes back, Only {0} can approve this. (「只有 {0} 能审批。」) replaces the buttons, in the accent colour; a 403 for an already answered or expired card shows nothing.
  - **Owner's DM:** the owner also gets a one-line reminder row (not a card, no buttons), `approval_reminder`: a dot, {0} is waiting for your approval in {1} (「{0} 在 {1} 等你审批」), and the time on the right. After the answer it reads Approved by you or Denied by you (「你已批准」「你已拒绝」), or Expired. The whole row opens the group and scrolls to the card.
  - **A host that sends no `ownerUserId` (v0.1):** the card is sent to the owner's DM and the group shows only the status card, `blocked` + `waitingFor: approval`, with `progress` Sent to owner's DM (`APPROVAL_SENT_TO_OWNER_DM_NOTICE`) and no Approve/Deny buttons; the group's copy of a bro-issued card is drawn with Sent to owner's DM and no buttons, and updates when the owner answers in the DM. If the task was already running in that DM, the card stays there and the notice is not shown.

## Routines

Open it from Settings, Bros, Routines (「例行任务」), or from the Routines row of a group profile. The Routines panel lists each group's routines (`GET /api/groups/{id}/schedules`) and can pause or resume them (`PATCH /api/schedules/{id}`). A paused routine is tagged Paused.

## Phone app

`robroz-mobile` (`mobile/`, Slint) shares the rules in `robroz-ui` (`settings.rs`, `cards/mcp.rs`, `home.rs`) and the tokens, so the pages above look the same on a phone, with these differences (`mobile/ui/app.slint`, `mobile/src/lib.rs`, `mobile/src/mcp.rs`):

- **Settings** has the General group (Language, Appearance, each opening a choice page with a tick), then, only when the app has a host connection, one MCP card, then the Sign out on this device card, then Version {0} (「版本 {0}」) with the app's crate version, 24px above the bottom edge plus the safe-area inset. It has no Bros rows and no Connection group; the host address and token are on the connect screen. Sign out clears the token the app holds (a token from the environment stays) and returns to the connect screen.
- **MCP** is read-only. The title row has the round ‹, MCP and, at its right end, {0} connected when at least one server is connected. The transport capsules show only when both transports exist. Each 64px row has the letter tile, the name, the grey line and Connect or Connected. There is no Add, Edit, Disconnect or Delete, and rows do not expand, so there is no tool list and no per-group switch. Connect does what it does on the desktop (enable, then test), and when the host answers 409 `command_not_approved` a bottom sheet shows the exact command and arguments with Cancel and Approve and run; approving runs `POST …/approve-command`, then `POST …/test`.
- Read-only is decided by platform, not window width (`Skin::can_edit`, false only when `Skin::phone` is set). When that skin is on, the iced MCP page hides Add server, Edit, Disconnect, Delete, Connect, the command-approve prompt and the group toggles; an expanded row can still show the tool list. The iced client in a window no wider than 480px only changes layout: those edit controls all stay.
- The phone app that ships is `robroz-mobile` (Slint). The iced client also has a phone skin, turned on with `ROBROZ_PHONE=1` (`client/src/main.rs`); it is for previews only and is not a released phone client. In v0.2 that skin hides Add, Edit, Disconnect, Delete, Connect, the command-approve prompt and the group toggles on the MCP page, but approval cards keep Approve and Deny and Settings keeps the desktop list.
- **Home list:** a row with no stored avatar glyph shows the first letter of the name, the same idea as iced `avatar_at`.
- **Approval row:** a pending card the viewer can answer shows Waiting for your approval: {0} (「等你批准：{0}」, `Key::ApprovalWaitingForYouDetail`), or Waiting for your approval when the summary is empty, plus a muted second line Approve or decline on desktop (「到桌面上批准或拒绝」, `Key::ApprovalHandleOnDesktop`). A pending bro card the viewer cannot answer shows Waiting for this bro's owner (「等这个 bro 的主人审批」, `Key::ApprovalWaitingFor`). A pending rule or settings card shows Waiting for an admin (「等管理员确认」, `Key::ReviewRulesWaitingForAdmin`). There are no Approve or Deny buttons on the phone in v0.2. When a task is waiting for approval and this read-only row is already shown, the task status pill is not drawn.
- The `#MadeWithSlint` badge is not shown anywhere. The client is `AGPL-3.0-only` and uses Slint under its GPLv3 option, which does not require the badge.

## Platforms and tests

- Running on Linux needs a graphical desktop, with `libxkbcommon-x11` (X11) or the Wayland libraries installed. The build itself does not need extra development packages.
- The client speaks HTTP or HTTPS (`ROBROZ_HOST`, or a saved `host` file next to `lang`). It sends `Authorization: Bearer <token>` on every request, including the live stream, when a token is set. `ROBROZ_HOST` and `ROBROZ_TOKEN` override any saved values for this run and are never written back. Otherwise the address comes from the `host` file, and the token comes from the OS keychain (Secret Service on Linux), falling back to a `token` file next to `lang` (mode `0600` on Unix). It does not read the host's `ROBROZ_TOKEN_FILE` variable. The token is never logged or shown. A 401 is shown as "The host rejected the token. Check ROBROZ_TOKEN." under the title "Token rejected" (「宿主拒绝了令牌，请检查 ROBROZ_TOKEN。」, title 「令牌被拒绝」). A host that cannot be reached is shown as "Can't reach host." (「连不上宿主。」), followed by the reason. The host itself does not do TLS; reach a remote host through an HTTPS reverse proxy or tunnel in front of it. The connection form reads [`load`](../client/src/conn/config.rs) and writes with [`save`](../client/src/conn/config.rs); after a successful save, build a new connection with `Conn::from_env`.
- `cargo test -p robroz-client` starts a real host router in-process and reads it back through `HttpSource`; Docker is not required.
